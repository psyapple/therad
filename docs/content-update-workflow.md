# 콘텐츠 수정과 배포 흐름

## 어떤 채널을 수정하면 어디에 반영되는가

| 원본 | 사이트에 반영되는 내용 | 반영 방식 |
| --- | --- | --- |
| 네이버 블로그 | 센터 소개, 최신 글 제목·분류·날짜·요약 | 다음 빌드에서 공개 RSS 자동 동기화 |
| 공개 노션 | 가이드 소개, 주요 목차, 상담 전 체크리스트 | 다음 빌드에서 공개 페이지 자동 동기화 |
| 인스타그램 | 프로필 링크 | 즉시 연결되어 있음 |
| Instagram Graph API | 최신 게시물 링크·캡션 | 공식 계정 ID와 토큰 설정 후 다음 빌드에서 동기화 |
| `lib/content.ts` | 상담 서비스와 사이트 자체 GUIDE | 코드 검토 후 반영 |
| `site-information-form.md` | 주소·가격·정책 등 실제 운영 정보의 원본 | 확정된 항목만 사이트 문구로 옮김 |

## 업데이트 절차

1. 블로그 또는 노션의 공개 원문을 수정합니다.
2. GitHub 이슈에 변경 목적과 확인할 링크를 남깁니다.
3. `npm run content:sync`로 공개 데이터를 갱신합니다.
4. 변경된 문구와 링크에 민감정보가 없는지 검토합니다.
5. `npm test`로 전체 페이지를 확인합니다.
6. GitHub에 커밋한 뒤 사이트를 배포합니다.

## GitHub에 올리지 않는 것

- 상담 기록, 신청서, 내담자 정보
- 댓글·답글·DM 원본 아카이브
- 자격증·사업자등록증·신분증 원본
- API 토큰, 비밀번호, 쿠키
- 동의받지 않은 후기와 인물 사진

## 콘텐츠 변경 단위

- 한 커밋에는 한 가지 목적만 담습니다.
- 제목 예시: `Update couple counseling price` 또는 `Sync June blog posts`
- 공개 사실과 홍보 문구를 구분합니다.
- 가격·자격·주소·정책 변경은 근거를 확인한 뒤 반영합니다.
- 자동 수집된 내용도 공개 전에 최소 한 번 사람이 확인합니다.
